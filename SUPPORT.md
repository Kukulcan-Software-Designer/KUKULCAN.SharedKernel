# Support

Thank you for your interest in **KUKULCAN.SharedKernel**.

This document explains how to obtain help, report issues and communicate with the project maintainers.

Please use the appropriate communication channel depending on the nature of your request.

---

# Before Asking for Help

Before opening a new Issue or Discussion, please verify the following:

- You are using the latest available version.
- You have read the README.
- You have checked the existing documentation.
- You have searched existing GitHub Issues.
- You have searched GitHub Discussions.
- The problem has not already been reported.

Many common questions are already answered in the documentation.

---

# Documentation

The following documents should always be your first reference.

- README.md
- CHANGELOG.md
- CONTRIBUTING.md
- SECURITY.md

They contain the project's architecture, usage guidelines and contribution rules.

---

# Reporting Bugs

If you believe you have found a bug, please create a GitHub Issue.

A good bug report should include:

- Framework version
- .NET version
- Operating System
- Complete exception message
- Stack trace (if applicable)
- Expected behaviour
- Actual behaviour
- Minimal reproducible example

Small reproducible projects greatly improve investigation time.

---

# Requesting New Features

Feature requests are welcome.

Before requesting a feature, please explain:

- The problem you are trying to solve.
- Why the current API is insufficient.
- Your proposed solution.
- Possible alternatives.

Architectural consistency always has priority over adding new functionality.

---

# Architectural Discussions

Questions regarding:

- Domain-Driven Design
- Clean Architecture
- Specifications
- Domain Events
- Results
- Value Objects
- Aggregate Roots

should preferably be discussed using GitHub Discussions.

This allows architectural decisions to remain visible for future contributors.

---

# Questions and General Help

General questions about using the framework should be asked through GitHub Discussions whenever possible.

Typical questions include:

- How to use a particular component.
- Recommended architectural patterns.
- Best practices.
- Migration guidance.
- Integration examples.

---

# Pull Requests

If you already know how to solve a problem, contributions are always welcome.

Please read:

CONTRIBUTING.md

before submitting a Pull Request.

---

# Response Expectations

Although every report is appreciated, response times may vary depending on:

- Severity
- Complexity
- Available maintainer time
- Current development priorities

Critical issues will always receive higher priority.

---

# Supported Versions

Only the latest released version is actively supported.

Older releases may not receive bug fixes or new features.

Please upgrade whenever possible.

---

# What Is Considered Out of Scope

The following topics are generally outside the scope of project support:

- General C# programming questions.
- ASP.NET Core tutorials.
- Entity Framework support.
- SQL Server administration.
- Visual Studio or Rider configuration.
- Operating System troubleshooting.
- Third-party library support.

Those questions are better addressed through their respective communities.

---

# Community Principles

The KUKULCAN.SharedKernel community values:

- Professionalism
- Respect
- Constructive feedback
- Technical discussion
- Architectural quality

Healthy disagreement is welcome.

Personal attacks are not.

Please follow the project's Code of Conduct.
